内容来源（API 中称为 Registry，注册表）是 MCP 管理器中的「市场来源」：每个内容来源对应一个市场 tab，提供搜索与安装入口。通过 `registry` capability 和 `ctx.registry.registerMcpRegistry`，插件可以把任意的 MCP Server 目录集成为 MCP 市场的内容来源，与内置内容来源在 UI、agent 工具和安装流程中完全同权。

OpenDesk 内置的内容来源就是按品牌组织的插件：[\`matrix\`](https://gitcode.com/openharmony-robot/OpenDesk/tree/main/resources/plugins/matrix) 与 [\`modelscope\`](https://gitcode.com/openharmony-robot/OpenDesk/tree/main/resources/plugins/modelscope) 两个插件各自同时集成 MCP 与技能两类来源，可以作为参考实现；仅集成技能来源的插件见[通过插件集成 Skill 市场](/docs/dev/plugins/skill-market/)。

## 能力声明

manifest 与入口对象都需要声明 `registry` capability：

~~~json
{
  "schemaVersion": 1,
  "id": "my-brand",
  "displayName": "My Brand",
  "entry": "./index.mjs",
  "apiVersion": 1,
  "capabilities": ["registry"]
}
~~~

## ctx.registry API

| 方法 / 字段 | 类型 | 说明 |
| --- | --- | --- |
| `registry.fetch` | `function` | 继承 OpenDesk 代理配置的 fetch；内容来源实现内的所有网络请求都应使用它 |
| `registry.registerMcpRegistry` | `function` | 集成一个 MCP 内容来源，返回 PluginRegistration |
| `registry.registerSkillRegistry` | `function` | 集成一个技能内容来源，见[通过插件集成 Skill 市场](/docs/dev/plugins/skill-market/) |

集成的内容来源 `id` 跨插件全局唯一（它同时是安装链接 `installUrl` 的前缀）。集成后，宿主把定义适配为与内置内容来源同构的对象：进入 MCP 管理器的 tab 列表与 `listMcpRegistries` / `searchMcpRegistry` / `installFromRegistry` 等工具的搜索与安装路由。在插件中心停用品牌插件后，其内容来源随宿主重载从市场移除（已打开的市场页面在重新打开后刷新）。

## MCP 内容来源定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 内容来源唯一标识，格式同插件 id；同时是 `installUrl` 前缀（`id:`），跨插件全局唯一 |
| `label` | `string` | 是 | 展示名称（市场 tab 文本） |
| `icon` | `string` | 否 | GUI 中的 emoji 图标，缺省为 `🧩` |
| `iconClass` | `string` | 否 | 预留的图标样式类名，缺省取 `id` |
| `slogan` | `string` | 否 | 热门条目页标语；缺省使用宿主默认文案 |
| `guiHidden` | `boolean` | 否 | `true` 时不在 GUI 市场出 tab（agent 工具仍可用） |
| `search` | `function` | 是 | `search(options?) => Promise&lt;McpSearchResult&gt;`，入参与技能侧一致（`query` / `page` / `limit` / `apiKey` / `cursor` / `categoryFilter`） |
| `getDetail` | `function` | 是 | `getDetail(id) => Promise&lt;RegistryMcp \| null&gt;`；安装流程（`installFromRegistry`）依赖它取回条目配置 |

`McpSearchResult`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `mcps` | `RegistryMcp[]` | 是 | 当前页条目 |
| `total` | `number` | 否 | 总数（用于分页展示） |
| `hasMore` | `boolean` | 否 | 是否还有下一页 |
| `nextCursor` | `string` | 否 | 游标分页时的下一页游标 |
| `message` | `string` | 否 | 展示在搜索结果上方的提示文案 |

`mcps` 中的条目（RegistryMcp）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 条目唯一标识；安装链接为 `id:` + 该值（含特殊字符时需 `encodeURIComponent`） |
| `name` | `string` | 是 | Server 名 |
| `description` | `string` | 是 | 描述 |
| `source` | `string` | 是 | 来源标识，通常与内容来源 `id` 一致 |
| `installUrl` | `string` | 是 | `id:` + 条目 id |
| `configuration` | `string` | 否 | 可安装的 MCP 配置 JSON（`mcpServers` 形式）；安装时宿主解析其中的 command / url / env 等 |
| `canInstall` | `boolean` | 是 | 是否可安装（需有 `configuration`） |
| displayName / author / repository / logo / deployType / serverType / downloads / stars / views / updateTime / tags / categories | — | 否 | 详情弹窗与卡片的展示字段 |

## installUrl 与安装流程

MCP 侧的 `installUrl` 约定为 `id:条目标识`。安装时宿主调用 `getDetail(条目标识)`，解析返回的 `configuration` 中的 `mcpServers` JSON 落成本地 MCP 配置。条目 id 含特殊字符时建议在 `installUrl` 中 `encodeURIComponent`，并在 `getDetail` 内自行解码。

`configuration` 的形式与标准 MCP 配置一致，stdio 与远程 Server 都可以表达：

~~~json
{
  "mcpServers": {
    "my-server": { "command": "npx", "args": ["-y", "@my-brand/my-server"] }
  }
}
~~~

## 示例

依赖 SDK：

~~~js
import { definePlugin } from '@bitclub.ai/opendesk-plugin-sdk';

export default definePlugin({
  id: 'my-brand',
  capabilities: ['registry'],
  setup(ctx) {
    ctx.registry.registerMcpRegistry({
      id: 'my-brand-mcps',
      label: 'My Brand MCPs',
      async search(options = {}) {
        const query = options.query || '';
        const res = await ctx.registry.fetch(
          `https://registry.my-brand.example/mcps?q=${encodeURIComponent(query)}`,
          { headers: { Accept: 'application/json' } }
        );
        const data = await res.json();
        return {
          mcps: data.items.map((item) => ({
            id: item.slug,
            name: item.name,
            description: item.summary,
            source: 'my-brand-mcps',
            installUrl: `my-brand-mcps:${item.slug}`,
            canInstall: Boolean(item.configuration),
            configuration: item.configuration
          })),
          total: data.total,
          hasMore: false
        };
      },
      async getDetail(id) {
        return {
          id,
          name: id,
          description: 'My Brand MCP server',
          source: 'my-brand-mcps',
          installUrl: `my-brand-mcps:${id}`,
          configuration: JSON.stringify({
            mcpServers: { [id]: { command: 'npx', args: ['-y', `@my-brand/${id}`] } }
          }),
          canInstall: true
        };
      }
    });
  }
});
~~~

不依赖 SDK 时默认导出同样的普通对象：

~~~js
export default {
  id: 'my-brand',
  capabilities: ['registry'],
  setup(ctx) {
    ctx.registry.registerMcpRegistry({
      id: 'my-brand-mcps',
      label: 'My Brand MCPs',
      async search() {
        return { mcps: [], total: 0, hasMore: false };
      },
      async getDetail(id) {
        return null;
      }
    });
  }
};
~~~

| --- | --- | --- |
| [matrix](https://gitcode.com/openharmony-robot/OpenDesk/tree/main/resources/plugins/matrix) | MCP `matrix` + 技能 `matrix` | OpenHarmony Matrix 市场 |
| [modelscope](https://gitcode.com/openharmony-robot/OpenDesk/tree/main/resources/plugins/modelscope) | MCP `modelscope-mcp` + 技能 `modelscope` | ModelScope（魔搭社区）市场 |

在插件中心可以按品牌独立启用 / 停用；停用后对应市场 tab 在页面重新打开时移除，重新启用后恢复。

## 行为与注意事项

- `search` / `getDetail` 的返回必须是可结构化克隆的纯数据（会跨线程传递给 worker 侧的市场搜索），不要在返回值中携带函数或宿主对象。
- 内容来源内的网络请求使用 `ctx.registry.fetch`，以继承宿主代理配置；直接使用全局 fetch 会绕过代理。
- `id` 是安装链接前缀，注册时宿主做跨插件全局唯一校验，重复注册会使插件 `setup` 失败并回滚本次已注册的项。
- 每次市场读取前宿主都会重新拉取当前生效的内容来源集合：插件重载后定义被替换（不会重复），插件停用 / 卸载后其内容来源从市场移除。
- `guiHidden` 只影响 GUI 市场 tab；agent 工具仍可搜索和安装该来源的内容。
- 一个插件可以同时调用 `registerSkillRegistry` 与 `registerMcpRegistry`，两类内容来源互不影响。
