渠道是插件市场与测评应用的内容来源：一份托管在某个地址上的清单 JSON，客户端定期拉取并展示里面的插件或测评集，用户点击后由 OpenDesk 下载归档包并完成安装。0.3.10 起，两类渠道都支持用户自行添加，团队和企业可以把内部插件、内部测评集发布到自己的市场上，不必进入官方渠道。

OpenDesk 内置两类渠道：

- **插件渠道**：插件市场的数据来源，清单里是插件包（`.zip` / `.tgz` / `.tar.gz`）；见[自建插件渠道](/docs/dev/custom-channels/plugins/)。
- **测评集渠道**：测评应用的数据来源，清单里是测评集压缩包（`.zip` / `.tar.gz` / `.tgz` / `.tar`）；见[自建测评集渠道](/docs/dev/custom-channels/benchmarks/)。

## 添加与管理

两类渠道的添加入口都在 **设置 → 渠道设置**：插件市场对应「插件渠道」，测评应用对应「测评集渠道」。每个渠道在对应应用里独占一个 Tab（Tab 名用渠道名）。

管理规则两类渠道一致：

- 系统默认（官方）渠道固定排在最前，地址内置写死，只能启用或禁用，不能改名、改地址或删除；
- 用户添加的自定义渠道最多 **20 个**，需要填写渠道名称与清单地址；
- 渠道名称不超过 80 个字符，且不能与已有渠道重名（大小写不敏感）；渠道地址也不能重复；
- 清单地址只接受 http(s)，`file:` 等其他协议一律拒绝；
- 添加或修改渠道时会联网校验：拉取清单并**严格**解析一遍（15 秒超时），任何一条写坏都会被拒绝保存——避免存下一个之后在界面上悄悄缺条目的渠道；
- 渠道配置保存在 `setting.json`：插件渠道在 `applications.pluginmgr.channels`，测评渠道在 `applications.benchmark.channels`，条目结构都是 `{ id, name, url, isEnabled }`。被禁用的渠道不拉清单、不占 Tab。

## 清单解析与缓存

客户端按下面的策略处理清单：

- **单条容错**：日常加载时某一条清单项写坏只跳过它并记 warning，不影响其他条目；整份清单一条都用不了才按「清单加载失败」处理，并回退到上次成功的缓存；
- **缓存 5 分钟**：避免切 Tab、点下载各自重复拉取远端清单；插件市场与测评应用里的刷新入口会强制绕过缓存重新拉取；
- **相对地址**：清单项里的下载地址可以写成相对于清单的路径（如 `plugins/demo.zip`），以清单自身地址为基准解析——清单和归档包放在同一个仓库或同一个目录下时，换域名、换分支都不用改清单；
- **下载地址安全**：https 清单只接受 https 下载地址；只有清单本身不是 https（本地调试文件、内网 http 市场）时才放行明文 http，防止线上市场的归档包被中间人替换。

## 本地调试

两处都提供环境变量，把内置官方清单替换成自己的地址，用于开发调试：

- 插件渠道：`OPENDESK_PLUGIN_CATEGORY`
- 测评集渠道：`OPENDESK_BENCHMARK_CATEGORY`

值可以指向本地 JSON 文件或自建服务的地址。指向本地文件时清单每次读取都直接读文件（改完立即生效，不走 5 分钟缓存），清单项的相对地址按该文件所在目录解析，明文 http 下载地址也会被放行。

官方渠道的清单就托管在 gitcode 上，是这两章描述格式的实际样例，可以直接参考：

- 官方插件渠道：[OpenDesk-Community/official-plugin-registry](https://gitcode.com/OpenDesk-Community/official-plugin-registry)（清单为仓库主线的 `category.json`）
- 官方测评集渠道：[OpenDesk-Community/official-benchmark-registry](https://gitcode.com/OpenDesk-Community/official-benchmark-registry)（清单为仓库主线的 `category.json`）
